# KAZ — казино для Telegram Mini App

Мобильное веб-приложение с шестью играми и внутренней валютой **★**. Баланс
пополняется за **Telegram Stars** по курсу **1 ★ = 1 Star**; вывод звёзд
оформляется заявкой, которая уходит администратору в Telegram.

## Что внутри

- **Слоты** — 5 линий, выплаты только за три одинаковых символа, до ×240 к линии.
- **Блэкджек** — выплата 6:5, дилер добирает мягкие 17.
- **Рулетка** — американское колесо с 0 и 00, 38 секторов.
- **Мины** — поле 5×5, пять мин, множитель до ×250.
- **Краш** — растущий множитель, краш до ×50, авто-закрытие при сворачивании.
- **Апгрейд** — выбор цели ×1.5…×10, шанс = 93% ÷ множитель.

Стартовый баланс — **50 ★**, ставка по умолчанию — **50 ★**, ежедневный
бонус — **10 ★**. Пополнение — от **1 ★**, по умолчанию **500 ★**, через
Telegram Stars. История, баланс и настройки хранятся в `localStorage` браузера
под ключом `kaz_demo_v1`; подтверждённые платежи дополнительно сохраняются в
приватном Vercel Blob и синхронизируются при открытии приложения.

## Математика

Шансы и RTP настроены в коде каждой игры. Отображаемые множители, выплаты и
правила остаются прежними. Звёзды — внутренняя игровая валюта; купить их можно
за Telegram Stars, но сами по себе они не являются Telegram Stars.

## Пополнение за Telegram Stars

В приложении: **«Пополнить» → ввести сумму → «Пополнить за Stars»**. Курс
**1 ★ = 1 Telegram Star**, минимум **1 ★**, максимум **10 000 ★**, значение по
умолчанию — **500 ★**. Также работает команда `/buy 500` в чате с ботом.

Сценарий:

1. Приложение отправляет боту сумму через `sendData`.
2. Бот создаёт счёт `sendInvoice` в валюте `XTR` (Telegram Stars).
3. Игрок оплачивает счёт в чате.
4. Webhook получает `pre_checkout_query` и `successful_payment`, проверяет
   сумму, валюту и уникальный `telegram_payment_charge_id`.
5. Платёж сохраняется в приватном Vercel Blob; при следующем открытии KAZ
   приложение получает подтверждённые пополнения через `/api/purchases` и
   зачисляет их на баланс. В «Истории» → «Пополнения» видна история зачислений;
   кнопка «Уже оплатил · проверить» запускает синхронизацию вручную.

Оплата создаётся через `sendInvoice`, потому что Shuza API не поддерживает
`createInvoiceLink`. Поэтому счёт открывается в чате с ботом, а не внутри
модального окна. После оплаты нужно вернуться в приложение.

## Вывод звёзд

В приложении: **баланс → «Вывод звёзд»**. Игрок указывает сумму (минимум
**500 ★**). Контакт для связи берётся из профиля ShuzaGram: имя, `@username`
и ID попадают в заявку администратору. Ручной ввод контакта не используется.
Заявка сохраняется локально, сумма резервируется, а бот пересылает её
администратору.

### Администраторы

1. Каждый администратор узнаёт свой ShuzaGram ID командой `/id` у бота.
2. Добавьте ID в переменную окружения `ADMIN_IDS` (несколько — через запятую).
   В Vercel: **Project → Settings → Environment Variables → Production**.
   Локально — в `.env`.
3. Перезапустите/передеплойте бота.

```env
ADMIN_IDS=111111111,222222222
```

В карточке заявки администратор видит кнопки **«✅ Выплачено»** и
**«❌ Отклонить»**. После нажатия карточка обновляется, а игрок получает
уведомление о решении.

Можно использовать и старый вариант `ADMIN_ID=111111111` для одного админа.

Если `ADMIN_ID`/`ADMIN_IDS` не задан, бот сообщит игроку, что администраторы
не подключены. Если клиент ShuzaGram не поддерживает `sendData`, приложение
не создаёт заявку и просит открыть KAZ через кнопку бота.

### Переменные окружения Vercel

Добавьте в **Production**:

| Переменная | Тип | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | Secret | токен бота |
| `ADMIN_IDS` | Config | ID администраторов через запятую |
| `WEBAPP_URL` | Config | `https://site-ten-sepia-56.vercel.app` |
| `SHUZA_API_BASE` | Config | `https://api.shuzagram.com` |
| `WEBHOOK_SECRET` | Secret | случайная строка, проверяется в `X-Telegram-Bot-Api-Secret-Token` |
| `BLOB_STORE_ID` | Config | добавляется автоматически при подключении Blob-хранилища `kaz-payments` |
| `VERCEL_OIDC_TOKEN` | Runtime | выдаётся Vercel автоматически; используется Python SDK `vercel-blob` |

Хранилище `kaz-payments` создано в Vercel (private, регион `iad1`) и
подключено к Production/Preview. OIDC не требует `BLOB_READ_WRITE_TOKEN` в
репозитории. Не добавляйте `.env` в Git и не коммитьте значения секретов.
Локальный `.env` остаётся только на машине разработчика.

### Обновление

После изменений в веб-части или `api/telegram.py` сделайте commit и push в
`main`. Vercel пересоберёт сайт и функцию автоматически. Для ручного деплоя:

```powershell
vercel deploy --prod
```

Проверка функции:

```text
GET https://site-ten-sepia-56.vercel.app/api/telegram
→ {"ok": true, "service": "kaz-telegram"}

GET https://site-ten-sepia-56.vercel.app/api/purchases
→ {"ok": true, "service": "kaz-purchases"}
```

### Webhook

Webhook уже включён. Если нужно включить его заново после смены домена:

```python
import bot
bot.api("setWebhook", {
    "url": "https://site-ten-sepia-56.vercel.app/api/telegram",
    "secret_token": "значение_WEBHOOK_SECRET",
    "allowed_updates": ["message", "callback_query", "pre_checkout_query"],
})
```

`getWebhookInfo` должен показывать этот URL и отсутствие ошибок. Не запускайте
одновременно локальный long polling и webhook: Telegram доставляет update только
одним способом.

## Локальный запуск (fallback)

Нужен Python 3.10+. Для локального запуска бота достаточно стандартной
библиотеки; для проверки пополнений установите `vercel-blob` из
`requirements.txt`.

```powershell
cd "C:\Users\Admin\Documents\Default Project"
python bot.py
```

`bot.py` сам удаляет webhook и переключается на long polling. Поэтому после
локального запуска не забудьте снова включить webhook, если возвращаетесь на
Vercel. Без `BOT_TOKEN` запустится только локальный веб-сервер:

```text
http://127.0.0.1:8080/
```

Для Telegram нужен публичный HTTPS-адрес.

## Ограничения

- Mini App в Telegram открывается только по HTTPS; `localhost` — только для
  локальной проверки.
- Пополнения подтверждаются Telegram и хранятся в Vercel Blob, но игровой
  баланс, ставки и история по-прежнему хранятся на устройстве. Это не
  серверный игровой счёт и не платформа для регулируемых азартных игр.
- Вывод — только заявка администратору с ручной проверкой; автоматических
  выплат нет. Минимум вывода — 500 ★.
- Serverless-функция имеет холодный старт; первый update после простоя может
  обрабатываться на секунду дольше.
- Токен бота не коммитьте и не публикуйте. `.env` исключён в `.gitignore`.
